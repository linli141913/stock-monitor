# 阶段 6L-D2 风险官方来源 POC 设计

## 1. 目标

阶段 6L-D2 验证阶段 6L-D1 七类风险合同所需官方来源的真实字段、历史检索、
公告修订和解除关系。D2 只建立隔离的来源发现适配器、Fixture 测试和真实只读
POC，不生成 D1 正式事件，不接生产运行时。

七类风险为：

- 减持；
- 解禁；
- 监管；
- 调查；
- 诉讼；
- 业绩；
- 审计。

## 2. 方案

采用代表性官方事件链 POC，不先做全市场历史回填。

1. 巨潮资讯负责发现公司披露、交易所披露和指定披露平台原文；
2. 证监会及派出机构原文用于核对监管、调查和行政处罚结论；
3. 沪深交易所监管措施、纪律处分和上市公司公告用于交叉确认；
4. 司法原文只接受明确文书，不把新闻、搜索结果或公司公告缺失解释为无诉讼；
5. 七类各取代表样本，并额外检查更正、提前终止、处罚结论和审计影响消除。

当前阶段不以关键词命中数证明全市场完整覆盖。

## 3. 来源分级

### 3.1 `official_document_discovery`

能够返回官方文档身份、发行人线索、发布时间和 HTTPS 原文：

- 巨潮资讯公告查询和 `static.cninfo.com.cn` 原文；
- 上交所、深交所上市公司公告；
- 上交所、深交所监管措施和纪律处分；
- 证监会及派出机构行政处罚、监管措施原文。

该等级只能发现和定位文档，不能单独生成 D1 风险事件。

### 3.2 `official_exact_document`

人工或确定性程序已经核对正文，取得 D1 分类专属字段：

- 减持计划区间和实施状态；
- 解禁生效日；
- 监管措施类型和文号；
- 调查案号；
- 诉讼案号和主体；
- 业绩报告期；
- 审计意见、报告期和报告编号。

该等级仍不等于上市以来查询完整。

### 3.3 `coverage_proof`

只有来源能够证明以下条件时才能建立 D1 覆盖证明：

- 从证券上市时间起连续查询；
- 查询类别版本和范围明确；
- 所有分页完整；
- 开放事件已结转；
- 更正和解除关系完整；
- 查询时间、来源时间和有效期可核验。

D2 实测来源均未达到该等级。

## 4. 巨潮资讯真实字段

官方查询入口：

`https://www.cninfo.com.cn/new/hisAnnouncement/query`

原文基址：

`https://static.cninfo.com.cn/`

2026-07-28 真实只读查询返回的可用字段：

- `secCode`；
- `secName`；
- `orgId`；
- `announcementId`；
- `announcementTitle`；
- `announcementTime`；
- `adjunctUrl`；
- `adjunctType`；
- `columnId`；
- `pageColumn`；
- `announcementType`；
- `associateAnnouncement`；
- `totalRecordNum`；
- `totalpages`；
- `hasMore`。

适配器固定：

- 文档身份使用 `cninfo:{announcementId}`；
- 发行人身份使用 `cninfo-org:{orgId}`；
- 原文只拼接 HTTPS `static.cninfo.com.cn`；
- `announcementTime` 按毫秒时间戳转换为上海时区；
- 标题只移除接口高亮标签，不解析为正式风险类别；
- `columnId` 和 `announcementType` 只保存原始代码，不猜测官方含义；
- `associateAnnouncement` 没有冻结语义前不得作为替代或解除引用。

## 5. 真实探针结论

### 5.1 七类关键词

查询区间为 2024-01-01 至 2026-07-28：

| 发现关键词 | 记录数 | 代表公告 ID | 元数据关联 |
| --- | ---: | --- | --- |
| 减持计划 | 9,057 | `1225445377` | `null` |
| 解除限售 | 7,750 | `1225443055` | `null` |
| 监管措施决定书 | 740 | `1225425872` | `null` |
| 立案告知书 | 343 | `1225443882` | `null` |
| 重大诉讼 | 1,420 | `1225442930` | `null` |
| 业绩预告 | 13,611 | `1225442898` | `null` |
| 审计报告 | 42,110 | `1225444265` | `null` |

以上记录数只表示全文检索命中，不表示七类正式事件数量或完整覆盖率。

适配器自身的真实只读核验使用“立案告知书”、每页 3 条。巨潮返回
`totalRecordNum=343`、`totalpages=114`、`hasMore=true` 和 3 条本页公告；
按记录数计算应为 115 页，官方分页元数据存在一页差异。适配器保留 3 条身份、
时间和 URL 均通过校验的本页文档，批次保持 `partial`，并记录
`cninfo_response_pagination_inconsistent`。这类不一致永远阻止完整覆盖声明，
但不伪装成本页文档全部不可用。

### 5.2 修订与解除

2020-01-01 至 2026-07-28 的代表查询：

| 发现关键词 | 记录数 | 代表公告 ID | 元数据关联 |
| --- | ---: | --- | --- |
| 业绩预告修正公告 | 851 | `1225425185` | `null` |
| 更正公告 | 7,361 | `1225443705` | `null` |
| 提前终止减持计划 | 1,736 | `1225443798` | `null` |
| 行政处罚决定书 | 969 | `1225430744` | `null` |

元数据没有提供稳定的 `supersedesDocumentId`、`targetEventId` 或
`targetEventVersion`。修订、提前终止和处罚结论需要正文中的原公告编号、案号、
报告期或人工审核映射，不能仅按证券代码和标题自动关联。

### 5.3 证监会

证监会及派出机构原文可以取得页面身份、索引号、文号、发布日期和决定正文。
行政处罚正文常包含“立案调查”和“调查、办理终结”，但：

- 页面不统一提供上市证券代码；
- 当事人与发行人身份需要精确核对；
- 处罚决定不一定关闭公司层面的全部持续风险；
- 中央站和各派出机构栏目结构不完全一致；
- 搜索或栏目列表不能证明上市以来完整覆盖。

因此证监会原文可作为精确官方文档，不能单独生成全市场覆盖证明。

### 5.4 审计样本

官方公告正文可以明确报告期、审计意见和审计报告编号。后续“非标准审计意见
涉及事项影响已消除”公告也能提供消除事实，但必须精确关联原报告期和原审计
报告，不得只凭标题关闭所有审计风险。

## 6. 来源适配器

新增 `backend/radar/sources/leader_risk_official.py`：

- `CninfoRiskDiscoveryQuery`：显式查询关键词、候选类别、日期窗口和分页；
- `OfficialRiskDocumentMetadata`：保存文档发现元数据；
- `OfficialRiskDiscoveryBatch`：保存来源状态、真实计数、分页和能力缺口；
- `parse_cninfo_risk_discovery_payload(...)`：纯解析 Fixture 或真实响应；
- `fetch_cninfo_risk_discovery(...)`：可注入传输函数的只读查询。

批次固定输出：

- `coverage_complete=false`；
- `open_event_carry_forward_complete=false`；
- `correction_links_complete=false`；
- `formal_usable=false`。

适配器不输出 `LeaderRiskEventEvidence`、`LeaderRiskResolutionEvidence` 或
`LeaderRiskEvidenceCoverage`。

## 7. 错误和缺失语义

- 网络或 HTTP 失败：`source_failed`；
- 响应结构、身份、时间或 URL 非法：`source_unverified`；
- 正常返回且元数据可解析：`partial`；
- 真实空查询保留 `total_records=0`，但仍不能证明无风险；
- 分页字段类型非法、返回行数超限或首页宣称有记录却为空时：
  `source_unverified`；
- 官方页数或 `hasMore` 与记录数计算不一致时：保留通过校验的本页文档，
  记录分页不一致原因，完整覆盖继续为假；
- 分页、行数或身份不一致时不丢弃原因；
- 未来公告时间、HTTP 原文、非官方域名和路径穿越全部拒绝；
- 单条脏记录使批次降级，不用其他记录补齐。

## 8. 明确不做

- 不从关键词或标题生成正式风险类别、子类型、案号、报告期或严重程度；
- 不下载或保存 PDF 正文；
- 不把 `associateAnnouncement=null` 解释为没有前序公告；
- 不把处罚决定自动解释为调查风险全部解除；
- 不建立上市以来完整覆盖声明；
- 不复用旧提醒、新闻或 AI 输出；
- 不新增依赖、数据库、迁移、仓储、调度、API、前端或提醒；
- 不读取或写入生产 SQLite；
- 不修改环境变量或阶段 6 开关；
- 不停止、重启或重载 4000/8001；
- 不执行 Git 暂存、提交或推送。

## 9. 验收

- Fixture 覆盖正常、空结果、脏字段、未来时间、非法 URL 和来源失败；
- 标题高亮被安全清理，原始分类代码保留；
- 文档、发行人、证券和时间身份稳定；
- 查询使用 HTTPS、显式日期窗口、分页上限、超时和直连会话；
- 七类和四类修订/解除关键词完成真实只读探针；
- 适配器真实只读探针保留 3 条本页官方文档，同时正确降级分页不一致；
- D2 专项 15 项、全部龙头 191 项、后端完整 752 项测试通过；
- 独立只读复核发现的短页/越界页、文档 ID 与 PDF 身份绑定、查询窗口
  时间校验问题均已修复，第二轮复核无 P1/P2 阻断；
- D1 官方域名注册表不扩张；
- D1 的 `CORRECTED` 继续 `source_unverified`；
- D1 正式覆盖、评分、门禁、状态机和 API 保持关闭。
