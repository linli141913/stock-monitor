# 阶段6L-C4A供应商交付与批次准入设计

## 目标

在不接入真实账号、不联网、不写数据库的前提下，冻结合规数据供应商进入C4真实POC前必须满足的交付血缘、授权、逐证券字段、整批覆盖和时效合同。C4A只判断数据是否具备进入POC的条件，不把供应商数据冒充交易所直连数据，也不开放评分、正式门禁或状态迁移。

## 选择

采用独立纯内存模块承接供应商候选数据，不修改C3的`OfficialDailyTradabilityReference`和`official_primary`准入语义。供应商记录只有在未来真实POC、来源核对和授权核对全部通过后，才允许由后续独立适配层转换为C3输入。

不采用以下方案：

- 不直接把供应商字段写入`OfficialDailyTradabilityReference`，避免伪造官方来源等级。
- 不从证券简称、零成交、无行情或上一交易日状态推断停牌、ST或可交易性。
- 不在C4A中安装SDK、配置账号、访问网络、缓存业务数据或接入运行时。

## 合同边界

新增`leader_tradability_provider_delivery.py`，包含六类冻结对象：

1. `ProviderAdmissionPolicy`：由系统侧单独注入可信供应商、交付合同、上游来源、授权文档、域名、使用范围和有效期白名单；供应商随记录自报的身份不能代替准入策略。
2. `ProviderLicenseEvidence`：只保存授权文档身份、HTTPS地址、授权范围、有效期和是否允许本地服务处理，不保存账号、Token、订单号或合同正文。
3. `ProviderSourceObservation`：分别绑定静态和动态来源的证券、交易日、来源合同、来源名称、文档身份、来源时间和内容摘要，防止跨证券、跨交易日或跨来源拼接。
4. `ProviderSourceProvenance`：保存供应商交付身份、交付等级、交付合同和批次，明确供应商不能覆盖上游来源身份。
5. `ProviderTradabilityDeliveryRecord`：保存C4逐证券字段，并把盘前静态参考时间与盘中动态交易状态时间拆开。
6. `ProviderTradabilityBatchInput/Result`：绑定统一交易日、运行时点、供应商、交付批次、目标证券全集和有序记录。

逐证券业务字段为：`symbol`、`exchange`、`board`、`trading_date`、`lifecycle_status`、`trading_status`、`special_session`、`price_limit_mode`、`upper_limit_price`和`lower_limit_price`。来源字段由授权、上游来源和供应商交付对象承担，不把两层血缘压成一个`source_name`。

## 时效语义

- 盘前静态参考以记录明确绑定的`trading_date`为有效性主键，不套用90秒盘中时效；其来源时间不得晚于当前运行时点加5秒。
- 盘中动态交易状态必须带时区，来源时间相对`as_of`不得超过90秒，未来偏差不得超过5秒。
- 供应商交付时间不得早于静态和动态来源时间，也不得晚于`as_of`加5秒。
- 静态和动态来源都必须明确绑定同一证券、交易日和交付批次；缺失或混批整批阻断。

## 批次准入

批次只有同时满足以下条件才返回`admissible_candidate`：

- 目标证券集合非空且唯一；每只目标证券恰好一条记录。
- 不存在缺失、重复、额外证券或错误交易日。
- 所有记录的供应商、交付合同、批次、上游来源合同和授权证据有效。
- 记录自报身份必须与系统侧独立准入策略完全匹配；缺少策略或白名单不匹配整批阻断。
- 静态与动态来源观测分别绑定同一证券和交易日，并具有可校验的SHA-256内容摘要。
- 生命周期、交易状态、特殊交易日和涨跌停模式均为已知枚举。
- `bounded`同时具有有限正数上下限且下限小于上限；`no_limit`上下限均为`null`。
- 授权在交易日有效并明确允许本地服务处理。
- 静态与动态时效均满足各自规则。

任一失败均返回稳定原因码和压缩证据，不回填旧值。结果中的`formal_score_ready`、`formal_gate_ready`、`formal_usable`和`state_transition_allowed`固定为`false`。

## 数据安全

对象`repr`和`to_evidence()`不包含账号、Token、授权正文、供应商响应正文或逐证券原始载荷。来源URL只接受无用户名、密码、查询参数和片段的HTTPS安全地址；带凭证URL直接阻断且不进入对象输出。批次证据只输出合同身份、数量、缺失/重复/额外证券、状态和原因；只有通过准入的候选批次才生成批次ID，且哈希绑定全部业务字段、来源观测摘要、授权和交付血缘。

## 测试

专项测试覆盖：完整沪深候选批次、独立准入策略、盘前静态时间早于90秒仍可接受、动态状态过期、未来时间、缺失/重复/额外证券、交易日混批、批次错配、授权过期、授权范围不足、静态/动态来源身份错配、未知枚举、`bounded/no_limit`价格语义、畸形运行时类型、敏感URL拒绝、内容哈希变化、冻结对象和压缩证据。完整后端回归必须继续通过。

## 明确不做

- 不申请或调用RQData、Tushare、Wind、Choice、iFinD账号。
- 不增加依赖、环境变量、数据库迁移、仓储、调度、API或页面。
- 不修改C3官方来源唯一准入等级。
- 不读取生产数据库，不重载4000/8001，不执行Git提交或推送。
