# 阶段 6L-D7 补录事实关系复核桥接设计

## 目标

为 D5 `fact_extraction_missing` 人工补录事实经过 D6 合并后，提供一次独立、版本化的关系复核入口。D7 只生成研究关系，不修改 D3 事实结果，不生成或解除 D1 正式风险事件。

## 输入与可信边界

D7 输入由三部分组成：

1. 完整的 `RiskDocumentResearchReplayInput`；
2. 调用方持有的 `RiskDocumentResearchReplayResult`；
3. 一次 `RiskDocumentVersionReview` 人工关系审核。

D7 必须使用第一项重新执行 D6，并与第二项逐字段相等后才继续。这样可以拒绝调用方自行构造或篡改的研究事实视图。

可复核的 D6 视图必须同时满足：

- 状态为 `ready`；
- 当前工件来自 `fact_extraction_missing` 候选；
- 当前视图存在人工补录事实；
- 当前视图尚无关系；
- 当前工件版本、内容哈希、文档、证券和发行人身份均通过 D6 重放验证。

## 关系审核合同

关系审核必须：

- 使用 `manual` 审核方式；
- 使用安全、唯一的审核 ID 和映射版本；
- 审核时间晚于当前 D5 工件审核时间，且不晚于 `as_of`；
- 精确引用当前文档、目标 D1 事件 ID 和事件版本；
- 目标事件属于同一证券与发行人，且目标文档早于当前文档；
- `basis_fact_ids` 全部存在于 D6 合并事实中，且至少引用一个 D6 人工补录事实；
- 引用目标文档编号事实；
- 调查或诉讼事件引用匹配案号，业绩或审计事件引用匹配报告期；
- `resolves` 不带替代事件版本；
- `supersedes` 必须带不同于目标版本的新事件版本。

审核已过有效期时返回 `stale`。合同、身份、版本、时间或依据不一致时返回 `source_unverified`。D6 未就绪时沿用 D6 的状态和原因。

## 输出

D7 输出独立的 `AcceptedSupplementedRiskDocumentRelation`，包含：

- 稳定关系 ID、审核版本和关系类型；
- 来源文档与目标事件精确版本；
- 全部事实依据及人工事实依据子集；
- D5 工件 ID/版本与 D6 重放版本；
- D7 合同版本。

输出固定：

- `formal_usable=false`
- `applied_to_d3=false`
- `applied_to_d1=false`

输出和对象 `repr` 不保存正文、人工原片段、D1 `fact_summary` 或审核 `decision_summary`。

## 明确不做

- 不连接或写入 SQLite；
- 不接 API、调度器或前端；
- 不修改 D3、D6 或 D1 对象；
- 不把研究关系提升为正式解除证据；
- 不实现关系历史仓库、批量审核或生产启用；
- 不新增依赖。

## 验证

- D7 专项测试覆盖成功、过期、伪造视图、错误事件版本、身份不一致、人工事实依据缺失、类别依据缺失和敏感文本隐藏；
- 运行 D1-D7 联合测试；
- 运行全部龙头测试；
- 运行后端完整测试和语法检查；
- 核对 Git diff、空白错误、服务 PID 与生产边界。
