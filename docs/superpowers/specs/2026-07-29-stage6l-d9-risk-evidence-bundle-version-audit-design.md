# 阶段 6L-D9 风险研究证据包版本链与差异审计设计

## 目标

把同一来源文档、同一内容快照和同一目标风险事件下的多个 D8 冻结证据包组成一条可复核的线性研究版本链，选择当前版本，并输出相邻版本间的结构化差异。

D9 只审计研究版本，不生成正式风险解除或替代证据，不修改 D1、D3 或 D8，也不连接数据库、调度、API 或前端。

## 方案选择

D9 输入采用按旧到新排列的 D8 证据包元组。元组顺序声明相邻替代关系，D9 使用严格递增的 `built_at`、唯一 `bundle_id` 和固定来源身份验证线性链。

不增加独立 `supersedes` 包装器，因为它会引入 D8 之外的人工元数据；不从 `v1`、`v2` 或人工审核版本名推断关系，因为名称不能证明真实替代顺序。

## 输入合同

`RiskResearchEvidenceBundleAuditInput` 只包含至少两个 `RiskResearchEvidenceBundle`，按旧到新排列。

所有证据包必须满足：

1. D8 合同版本为 `radar-leader-risk-research-evidence-bundle-v1`；
2. `bundle_id` 唯一，`built_at` 为带时区时间且严格递增；
3. 来源合同、文档 ID、证券、发行人、内容合同、内容哈希和内容抓取时间完全一致；
4. 目标事件 ID 和目标文档 ID 完全一致；
5. D8 的 `formal_gate_ready`、`formal_usable`、`applied_to_d3` 和 `applied_to_d1` 均为 `false`；
6. 正式门禁缺口为无重复的 `FormalRiskGateGap`；
7. 每个后继包相对前驱至少存在一项可审计实质变化，不能只改变 `built_at` 或 `bundle_id`。

输入不是合同对象、少于两个包、混入其他来源快照、乱序、重复或没有实质变化时，不选择当前版本，也不输出部分差异。

## 输出合同

`RiskResearchEvidenceBundleAuditResult` 使用冻结 dataclass，包含：

- 研究状态；
- 全部按顺序排列的证据包 ID；
- 当前证据包和当前证据包 ID；
- 每一对相邻版本的 `RiskResearchEvidenceBundleVersionDiff`；
- 稳定原因代码；
- D9 合同版本；
- 固定关闭的正式门禁和应用标志。

相邻版本差异分为四组：

1. **事实差异**：确定性、人工和合并事实 ID 的新增与移除；
2. **人工工件差异**：工件 ID、审核版本和工件合同版本的字段变化；
3. **研究关系差异**：重放版本、关系 ID、审核 ID、映射版本、关系类型、目标事件版本、替代事件版本、目标事件官方状态和发布时间的字段变化，以及普通依据和人工依据事实 ID 的新增与移除；
4. **正式门禁缺口差异**：缺口枚举的新增与移除。

字段变化使用冻结的 `RiskEvidenceFieldChange`，只保存字段名、旧值和新值。日期统一为 ISO 8601 字符串，枚举统一为稳定值，缺失值保持 `None`。

## 当前版本选择

通过全部合同校验后，输入中的最后一个证据包是当前研究版本。D9 不根据字符串大小、工件版本名或关系版本名重新排序。

如果任一相邻版本没有实质变化，或整条链任一位置不可信，结果整体为不可验证，不返回当前版本。

## 安全与隐私

D9 只保存 D8 已压缩的标识、枚举和时间，不保存来源 URL、公告标题、正文、事件摘要、人工审核摘要、原始人工值或 PDF 片段。

所有输入对象在结果 `repr` 中隐藏；输出保持不可变，不提供写回上游对象的函数。

## 明确不做

- 不自动合并分支、冲突或乱序版本；
- 不猜测缺失的中间版本，也不声称历史完整；
- 不生成、替代或解除 D1 风险事件；
- 不把研究关系应用到 D3；
- 不提升正式状态或正式可用性；
- 不连接生产 SQLite，不新增迁移、仓储、调度、API、前端或运行开关；
- 不引入新依赖；
- 不调用 AI。

## 验收

1. 两个及以上合法 D8 包形成确定性线性链，最后一个被选择为当前版本；
2. 四组差异都按输入顺序稳定输出；
3. 三个及以上包输出相邻差异，不跨版本压缩；
4. 混合身份、乱序、重复、合同伪造和无实质变化均稳定拒绝；
5. 结果和差异对象不可变，不泄露敏感文本；
6. D1-D9 联合测试、龙头全量测试、后端完整回归、语法检查和 `git diff --check` 通过。
