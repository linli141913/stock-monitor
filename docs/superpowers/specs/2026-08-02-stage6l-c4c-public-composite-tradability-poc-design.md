# 阶段6L-C4C免费组合源可交易性POC设计

## 目标

在不购买数据订阅、不改变阶段6正式评分和状态机的前提下，验证现有腾讯行情、
交易所公开材料和项目已安装的AKShare公开数据聚合能力，能否共同覆盖三级龙头
所需的证券生命周期、ST、停复牌、盘中交易状态和当日涨跌停边界。

C4C只形成可审计的免费组合源候选，不把公开网页、简称或单一供应商字段冒充
交易所正式参考文件。RQData C4B适配器继续保留为可选对照窗口，默认关闭，
没有账号或Token时不得影响免费路径。

## 决策

采用“免费组合源优先、RQData可插拔备用”的双路径设计：

1. 免费路径先完成隔离字段POC和连续影子观察；
2. RQData路径保留现有字段合同和一次性入口，不接生产运行时；
3. 两条路径都转换为同一中立字段矩阵后再比较，不让供应商身份进入评分公式；
4. 免费路径通过前不替换C3的`official_primary`语义，也不打开正式门禁；
5. 后续若RQData试用获批，可作为有界对照源，不成为运行必需依赖。

不选择“RQData直接作为主源”，因为当前字段范围不足以证明长期订阅成本合理。
不选择“腾讯单源直接启用”，因为它不能独立证明完整生命周期、ST和停复牌事实。
不选择“公告未命中即正常交易”，因为未发现公告不等于证券一定可交易。

## 变更分类

- **保留**：C1研究合同、C3官方来源合同、C4A供应商交付合同和C4B RQData适配器。
- **新增**：免费组合源逐证券观测、来源一致性审计和脱敏POC报告。
- **增强**：只复用腾讯同一批行情已解析的源时间、交易状态、昨收和上下限字段，
  不增加腾讯请求次数。
- **暂缓**：生产运行时、数据库、调度、API、页面、正式评分和状态机接入。
- **不替换**：C4C通过前不修改`tradability_passed`和任何正式候选结果。

## 来源职责

| 字段 | 主证据 | 交叉校验 | 当前准入边界 |
| --- | --- | --- | --- |
| 证券身份、交易所、板块、上市日期 | 沪深交易所公开证券列表 | 现有证券主档 | 可做当前与向前观察 |
| 终止上市等生命周期 | 交易所公开列表或原文公告 | AKShare交易所接口 | 公告必须绑定公布和生效时间 |
| ST、*ST | 交易所风险警示信息或公司原文公告 | AKShare风险警示板；腾讯简称只用于发现冲突 | 简称不得单独生成状态 |
| 全天停复牌 | 交易所停复牌公告 | AKShare `stock_tfp_em` | 未命中不得推断为正常 |
| 盘中异常状态 | 腾讯同批行情显式`S/D/U`状态和源时间 | 交易所盘中停牌公告 | 必须是同交易日且不超过90秒 |
| 昨收、当日上下限 | 腾讯同批行情字段 | C3版本化交易规则 | 冲突即降级；不自行修补 |
| 无涨跌幅限制特殊日 | 交易所上市、重新上市或退市整理公告 | C3规则目录 | 必须有逐证券特殊日证据 |

AKShare只作为公开数据聚合层。它返回的东方财富、交易所或其他上游内容必须保留
原上游名称、目标页面和源日期，不能统一改写为“AKShare官方数据”。

## 中立字段合同

新增纯内存POC模块，逐证券候选记录至少包含：

- `symbol`、`exchange`、`board`、`trading_date`；
- `lifecycle_status`、`trading_status`、`special_session`；
- `price_limit_mode`、`upper_limit_price`、`lower_limit_price`；
- 每个字段自己的主源、备用源、源时间、抓取时间和证据摘要；
- 一致、冲突、缺失、过期和来源失败状态；
- 固定的`formal_score_ready=false`、`formal_gate_ready=false`、
  `formal_usable=false`和`state_transition_allowed=false`。

输出不得包含上游响应正文、逐证券公告正文、账号、Token、请求头或带查询参数的
敏感URL。内容审计只保存来源合同、行数、覆盖率、时间范围和SHA-256摘要。

## 时效和延迟窗口

- 腾讯盘中行情相对`as_of`最大允许延迟90秒，未来偏差最多5秒；
- 腾讯当前合同只把显式`S/D/U`映射为暂停、退市或未上市；普通行情行、当前价格
  或非零成交不能自动生成`trading`。只有后续POC取得明确且可复验的正常状态字段
  合同，或获得同交易日正式参考，才允许填充正常交易状态；
- 停复牌、ST和生命周期静态证据以交易日及明确生效区间为准，不套用90秒；
- 盘前静态批次必须在当日首次候选计算前完成；缺失时整批保持研究不可用；
- 交易所盘中临停公告只覆盖已发布事件，不能反向证明其余证券均为正常；
- 免费源允许比付费聚合源更保守，但不允许用旧值补成当前结果；
- 任一必需字段冲突、过期或未知时，该证券不得进入正式状态迁移。

## RQData备用窗口

- 保留`leader_tradability_rqdata_poc.py`和单次真实POC入口；
- 不删除、不改写其固定端点、脱敏、样本上限和无自动重试边界；
- 默认不读取账号、密码、Token或环境变量，不注册后台任务；
- 未来试用获批时，只在有效交易窗口执行一次字段对照；
- RQData结果与免费路径使用相同证券、交易日和字段矩阵比较；
- RQData失败、到期或未配置不得使免费路径失败，也不得产生付费重试。

## 状态与冲突策略

POC结果只允许：

- `field_candidate`：目标字段、身份、日期、时间和交叉校验均通过；
- `partial`：部分字段缺失、来源未覆盖或仅具备单源候选；
- `blocked`：身份错配、交易日混批、字段冲突、未来时间或不安全来源；
- `not_run`：未执行真实公开源请求；
- `no_data`：真实请求成功但没有可验证记录。

来源优先级为交易所原文、交易所公开结构化列表、腾讯同批行情、明确上游的
AKShare聚合结果。优先级不能掩盖冲突：高低优先级来源不一致时仍返回冲突，
等待新证据，不选择更符合预期的一方。

## 测试与真实验收

Fixture测试必须覆盖：

- 普通、ST、*ST、停牌、终止上市、新股和无涨跌幅限制样本；
- 腾讯普通行情但无显式正常状态、`S/D/U`状态、真实0、空值、过期和未来时间；
- 交易所与AKShare一致、冲突、缺失和来源失败；
- 公告未命中不能生成`trading`；
- 上下限与C3规则一致和冲突；
- 证券缺失、重复、额外、错误交易日和混合批次；
- RQData未配置时免费路径不受影响；
- 报告脱敏及所有正式开关持续为`false`。

真实POC在有效A股交易日执行，先从不超过8只样本开始，至少覆盖普通、风险警示、
停牌和特殊交易日中的当日可获得类别。只统计字段覆盖、来源时间、冲突、耗时和
响应摘要，不读取或写入生产SQLite，不保存上游正文。

免费路径是否能进入后续影子桥接，至少要求：

- 本轮目标证券身份和行覆盖率100%；
- 必需字段覆盖率100%，或缺失证券明确阻止候选；
- 盘中动态字段满足90秒时效；
- 交易所原文抽查无冲突；
- 连续影子期间不使用旧状态补本轮结果。

单次POC通过不等于正式可用。正式桥接仍需独立版本合同，并复用雷达至少20个
交易日影子观察验证延迟、断流、冲突率和特殊样本误判。

## 明确不做

- 不安装或升级依赖；优先使用项目已有AKShare和标准库。
- 不购买、续费或自动申请任何数据服务。
- 不把简称、价格为0、成交为0或无行情推断为ST或停牌。
- 不从上一交易日复制状态，不用抓取时间冒充源时间。
- 不修改数据库迁移、仓储、调度、API、前端、提醒或AI。
- 不读取或写入生产SQLite，不修改环境变量和LaunchAgent。
- 不停止、重启或重载4000/8001。
- 不执行Git暂存、提交、推送、部署或创建PR。

## 回退

C4C保持独立且未接运行时。回退只需撤回新增POC模块、测试和设计/计划文档；
C1、C3、C4A、C4B、当前生产服务、阶段5观察和阶段6既有研究链路均不受影响。
