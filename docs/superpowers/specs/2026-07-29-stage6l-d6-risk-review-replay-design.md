# 阶段 6L-D6 审核工件重放与研究事实合并设计

## 1. 目标

阶段 6L-D6 消费 D2 文档、D4 内容、D3 基础事实和 D5 已接受人工审核工件，
选择唯一当前版本，生成不修改 D3/D1 的研究事实视图。

D6 必须：

- 重新计算 D3 基础事实和 D4 人工候选；
- 验证 D5 工件的完整线性版本链；
- 只选择最后一个版本，不回退已被替代版本；
- 合并 D3 确定性事实与 D5 人工事实，但不覆盖确定性事实；
- 重放 D5 已接受关系，并重新核对目标事件、事实依据和版本身份；
- 输出清晰的确定性、人工和合并来源审计。

## 2. 方案取舍

采用方案 A“独立研究视图重放器”：

1. D3 保持确定性抽取器，不增加人工输入；
2. D5 保持不可变审核工件；
3. D6 只负责验证、选择和组合；
4. 输出是新的研究视图，不反写任何上游对象。

不采用：

- 直接把 D5 人工事实写回 D3 结果；
- 当前阶段新增数据库、仓储、运行时或人工审核页面。

## 3. 模块边界

新增：

`backend/radar/leader_risk_review_replay.py`

该模块：

- 只做内存纯计算；
- 不联网、不读写文件、不连接数据库；
- 不调用 AI 或 OCR；
- 不修改 D1-D5 对象；
- 不接迁移、仓储、运行时、调度、API、前端或提醒。

## 4. 输入合同

`RiskDocumentResearchReplayInput`：

- `as_of`；
- D2 `OfficialRiskDocumentMetadata`；
- D4 `OfficialRiskDocumentContentResult`；
- 未包含人工关系的 D3 `OfficialRiskDocumentFactResult`；
- D1 已知事件版本；
- 按审核时间排列的 D5 `AcceptedManualRiskReviewArtifact` 集合。

D6 使用当前文档、内容和事件版本重新调用 D3，结果必须与输入 D3 结果完全相等；
然后使用 D4 构造器重新生成候选。任何身份、哈希、页数、事实或候选漂移均拒绝。

## 5. 版本链重放

每条工件链必须满足：

- 全部工件属于同一个候选和稳定工件 ID；
- 首版 `supersedes_review_version=null`；
- 后续版本逐一精确引用前一版本；
- 审核版本唯一，审核时间严格递增且不晚于 `as_of`；
- 文档、证券、发行人、PDF 哈希和候选类型始终一致；
- 工件合同版本、人工审核方法和非正式标志不变；
- 事实候选只包含人工事实，关系候选只包含接受关系；
- 旧版本可以已过期，但最后版本一旦过期，整次重放返回 `stale`；
- 不得回退到被最后版本替代的旧版本。

## 6. 人工事实重放

人工事实必须继续满足：

- `extractor_version=radar-leader-risk-document-manual-review-v1`；
- 事实 ID 与文档、类型、归一化值和页码一致；
- 片段 SHA-256 为 64 位小写十六进制；
- 页码在当前 D4 页数内；
- 归一化值符合六类 D3 事实格式；
- 同类多值冲突拒绝。

合并规则：

- D3 确定性事实优先；
- 人工事实与确定性事实完全相同时只保留确定性事实；
- 同一事实类型出现不同值时拒绝，不允许人工覆盖；
- 输出分别保留 `deterministic_facts`、`manual_facts` 和合并后的 `facts`。

## 7. 关系重放

D5 接受关系必须重新核对：

- 当前文档 ID；
- 映射版本等于当前工件审核版本；
- 审核时间等于当前工件审核时间；
- 目标 `event_id + event_version` 在 D1 输入中精确存在；
- 目标文档、证券和发行人与事件一致；
- 全部 `basis_fact_ids` 存在于当前 D3 确定性事实；
- 调查/诉讼的案号事实与目标事件一致；
- 业绩/审计的报告期事实与目标事件一致；
- `supersedes/resolves` 的替代版本规则继续有效。

D6 不接受人工事实工件直接携带关系；事实补录后的进一步关系审核属于后续阶段。

## 8. 输出合同

`RiskDocumentResearchReplayResult`：

- `status`；
- 文档、证券、发行人和 PDF 哈希；
- `deterministic_facts`；
- `manual_facts`；
- 合并 `facts`；
- 接受关系；
- 当前工件 ID 和审核版本；
- `manual_review_applied_to_view`；
- `d3_mutated=false`；
- `formal_usable=false`；
- `applied_to_d1=false`；
- `correction_links_complete=false`；
- 稳定原因码。

输出不包含页文本、人工原始值、片段、事件摘要或审核摘要。

## 9. 状态语义

- 有效当前工件：`ready`；
- 候选存在但没有工件：`missing`；
- 最后工件已过期：`stale`；
- D3/D4 来源失败或不可信：保留上游状态；
- 候选、工件链、事实合并或关系重放不可信：`source_unverified`；
- 不把缺少工件解释为没有风险。

## 10. 明确不做

- 不把人工事实写回 D3；
- 不让人工事实自动生成关系；
- 不生成 D1 风险事件或解除证据；
- 不新增数据库、迁移、仓储、运行时、调度、API、前端或提醒；
- 不新增依赖；
- 不读取或写入生产 SQLite；
- 不修改环境变量或服务；
- 不执行 Git 暂存、提交或推送。

## 11. 验收

- 合法事实工件链选择最后版本并输出合并研究事实；
- 合法关系工件链重放精确关系；
- 空工件、最新过期、未来审核、重复版本、分叉和跨候选有稳定语义；
- 伪造事实 ID、片段哈希、页码、归一化值和关系依据被拒绝；
- 人工事实不能覆盖 D3 确定性事实；
- 输出和 `repr` 不泄露正文、原始值、片段或摘要；
- 全部结果保持非正式且不修改 D3/D1；
- D1-D6、全部龙头和后端完整测试通过；
- 语法、差异和只读安全复核通过。

## 12. 实施结果

阶段 6L-D6 已按独立研究视图方案完成：

- 每次重放重新计算 D3 基础事实并重建 D4 候选；
- 完整验证 D5 工件 ID、候选身份、审核时间、版本引用、事实或关系载荷；
- 只选择最后版本，最后版本过期时返回 `stale`，不回退旧版本；
- 人工事实 ID、归一化值、页码、片段哈希和来源版本均重新校验；
- 关系重新核对当前事件版本、原文档事实依据、案号或报告期；
- 畸形嵌套标识和 `None` 关系集合稳定返回 `source_unverified`；
- 输出分别保留确定性事实、人工事实和合并事实，不修改 D3；
- 全部结果保持 `formal_usable=false`、`d3_mutated=false` 和
  `applied_to_d1=false`。

本阶段没有运行真实人工工件重放；Fixture 只验证合同与版本语义。
