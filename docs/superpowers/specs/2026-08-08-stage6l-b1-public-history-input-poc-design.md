# 阶段6L-B1免费历史输入POC设计

## 1. 目标

为现有 `leader_history_features` 提供一个隔离、只读、免费来源的真实输入
POC，验证候选股票、当时有效行业成员等权基准和交易所板块指数最近21个
交易日的历史序列能否按同一日期口径组装。

本阶段只验证来源和输入合同，不接生产运行时，不写数据库，不冻结正式分数，
不允许龙头状态迁移。阶段6L-C4C-2B仍在有效交易时段独立执行。

## 2. 方案选择

采用“官方行业版本 + 腾讯前复权日线 + 严格完整覆盖”方案：

- 上交所官方休市页提供最近21个已完成交易日；
- 中上协官方行业分类结果提供大类和成员版本，成员范围只保留项目支持的
  上交所、深交所证券；
- 腾讯财经日K提供候选、全部范围内行业成员和板块指数的价格序列；
- 行业基准按每个交易日全部成员价格收益等权平均并连续复合；
- 任一成员缺日、非法价格或来源身份不明时，不输出可接入的历史输入。

不采用两个替代方案：

- 不用现成行业指数替代当时成员等权基准，二者权重和成员口径不同；
- 不用当前聚合行业成员回填历史，因为会产生未来数据和幸存者偏差。

## 3. 合同与状态

纯内存POC输入包含：

- 带时区的 `as_of`；
- 21个官方交易日；
- 候选证券和对应板块指数；
- 中上协发布ID、文档摘要、分类起始日、首次观察时间和行业成员；
- 每个证券的腾讯来源合同、内容摘要、抓取时间和前复权收盘值。

POC输出区分：

- `completed`：行业版本从窗口首日前已被本系统观察，且全部价格序列完整；
- `partial`：真实来源有返回，但行业版本前向观察或成员价格覆盖不完整；
- `failed`：官方日历、行业文档或价格来源请求/解析失败；
- `not_run`：未确认真实调用或证券参数非法；超过最多80个行业成员预算时，
  已完成的官方来源核对保留为 `partial`，但不发起历史价格批量请求。

Fixture测试不得产生 `realPocStatus=completed`。所有结果固定：

- `formalScoreReady=false`；
- `formalGateReady=false`；
- `formalUsable=false`；
- `stateTransitionAllowed=false`。

## 4. 时间与真实性边界

- 最新交易日必须已经收盘；盘中只能取上一已完成交易日。
- 行业分类起始日必须覆盖21日窗口，发布日期不得晚于窗口末日。
- `first_observed_at` 晚于窗口首日时，只能标记 `partial`，不能冒充点时输入。
- 北交所等范围外证券不进入成员数量、序列数量或覆盖率分母，只记录
  `excludedOutOfScopeCount` 供审计。
- 腾讯返回必须逐日匹配官方交易日；停牌造成的缺日不能自动当作0收益。
- `fund_flow=0`、价格收益0和缺失数据继续严格区分。
- 只保存规范化摘要、覆盖率和原因；证据输出不含原始响应正文。

## 5. 组件

- `backend/radar/sources/leader_history_public_poc.py`：纯合同、腾讯载荷解析、
  等权基准构造和既有 `LeaderHistoryFeatureInput` 适配。
- `backend/run_public_history_poc.py`：一次性CLI，显式确认后调用官方页面和免费
  历史源，最多一个候选、80个行业成员、8路并发、每请求8秒。
- 两个专项测试文件分别覆盖纯合同和CLI门禁/脱敏。

## 6. 明确不做

- 不读取或写入生产SQLite；
- 不新增依赖、迁移、缓存、环境变量或调度；
- 不接 `runtime.py`、仓储、API、页面、提醒或AI；
- 不因POC数据完整而打开正式评分或状态机；
- 不重启4000/8001，不执行Git暂存、提交、推送或部署。

## 7. 验收

- 测试先证明模块缺失或行为缺失，再完成最小实现；
- Fixture覆盖完整等权计算、真实0、成员缺日、错行业、未来时间和晚观察；
- CLI覆盖未确认、非法证券、预算超限、异常脱敏和Fixture不能伪装真实完成；
- 运行阶段6龙头相关回归和 `git diff --check`；
- 执行一次闭市可运行的真实历史样本POC，并按 `completed/partial/failed`
  如实汇报。
