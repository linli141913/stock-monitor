# 阶段 6L-D1 风险与失效官方证据合同设计

## 1. 目标

阶段 6L-D1 建立统一、版本化、可追溯且可被官方解除证据关闭的风险研究合同，
覆盖减持、解禁、监管、调查、诉讼、业绩和审计七类风险。

本阶段只校验调用方显式提供的结构化官方证据，不自动抓取公告，不生成正式
风险结论，不改变 `risk_filter_passed`、评分、状态机、只读 API 或生产配置。
阶段 5 的交易日影子观察和数据源稳定性观察继续并行。

主营与催化关联被证伪继续由阶段 6L-B3 合同负责，D1 不重复定义。

## 2. 方案选择

采用“统一风险事件合同 + 分类专属校验 + 官方解除证据 + 查询完整性证明”。

七类风险共用证券身份、事件版本、官方原文、发布时间、生效区间、解除关系、
冲突和缺失语义。分类差异由专属校验规则处理，不为每类风险复制一套完整模块。

现有提醒中心的官方事件负载只面向提醒展示，缺少知识版本、有效区间、解除闭环
和空结果覆盖证明，不作为 D1 的正式输入合同。

## 3. 证据来源

### 3.1 可接受来源

- 上市公司正式公告、定期报告、业绩预告和审计报告；
- 上海、深圳或北京证券交易所正式披露；
- 中国证监会及其派出机构、证券交易所监管措施和纪律处分原文；
- 巨潮资讯等交易所指定信息披露平台保存的公司原文；
- 人民法院、仲裁机构或其他有权机关公开的正式文书，但必须能精确关联证券
  和上市公司主体。

D1 只接受冻结的
`radar-leader-risk-official-coverage-v1` 来源合同和
`radar-leader-risk-official-coverage-adapter-v1` 适配器合同。来源类型与
官方域名按版本化注册表绑定；调用方自报来源名称或任意 HTTPS 地址不能成为
官方证据。D2 真实来源 POC 验收前不得新增注册项。

### 3.2 不可作为通过依据

- 普通新闻、媒体标题、研报摘要、社交媒体或搜索结果摘要；
- 主题标签、概念板块、关键词命中或自然语言情绪；
- AI 生成的风险分类、严重程度、解除结论或有效期；
- 没有 HTTPS 原文链接、稳定文档身份、发布时间或主体身份的二手描述；
- 仅凭股价、成交、资金流、简称、停牌或页面未返回结果推断风险。

以上内容最多作为待验证线索，不进入 `ready` 结果。

## 4. 统一输入合同

新增纯计算模块 `backend/radar/leader_risk_invalidation_features.py`。
模块不发网络请求、不读取数据库、不读取环境变量。

### 4.1 风险事件

`LeaderRiskEventEvidence` 至少包含：

- `event_id` 和 `event_version`：稳定事件身份及知识版本；
- `symbol` 和 `issuer_identity`：证券与发行人身份；
- `category`：`reduction`、`unlock`、`regulatory`、`investigation`、
  `litigation`、`earnings` 或 `audit`；
- `event_subtype`：受类别约束的结构化子类型；
- `case_id`：调查和诉讼必填的官方案件身份，其他类别为空；
- `source_kind`、`source_name`、`source_url` 和 `document_id`；
- `published_at`、`effective_from` 和可选 `effective_until`；
- `reporting_period`：业绩或审计风险的对应报告期，其他类别为空；
- `fact_summary`：压缩结构化事实，不保存完整公告正文；
- `official_status`：`active`、`completed`、`withdrawn` 或 `corrected`。

调用方不能通过自定义“严重程度”直接影响正式结果。D1 只记录官方事实类别和
当前有效状态，不冻结正式风险权重或移出阈值。

`corrected` 不表示风险解除。D1 尚未接真实修订链，因此当前事件标记为
`corrected` 或同一事件出现多个版本时统一返回 `source_unverified`，等待
D2 冻结替代版本的知识生效区间后再开放。

### 4.2 官方解除或修正

`LeaderRiskResolutionEvidence` 至少包含：

- `resolution_id` 和 `resolution_version`；
- `target_event_id` 和 `target_event_version`：必须精确引用同一输入中的
  单个风险事件版本；
- `symbol` 和 `issuer_identity`；
- `resolution_kind`：`completed`、`withdrawn`、`corrected` 或
  `officially_cleared`；
- `source_kind`、`source_name`、`source_url` 和 `document_id`；
- `published_at` 和 `effective_from`；
- `resolution_summary`：压缩解除或修正事实。

风险不能因为长时间没有新公告、网页空榜或系统当前时间超过任意默认天数而
自动解除。只有事件自身的正式完成/撤回状态、明确有效期结束，或精确匹配事件
版本的 `completed`、`withdrawn`、`officially_cleared` 官方解除证据才能
关闭。`corrected` 解除记录当前返回 `source_unverified`，不得静默关闭风险。

### 4.3 查询完整性证明

`LeaderRiskEvidenceCoverage` 用于区分“已完整检查且没有风险”和“没有数据”：

- `coverage_id` 和 `source_contract_id`；
- `adapter_contract_id`；
- `symbol` 和 `issuer_identity`；
- `issuer_listed_at`；
- `covered_categories`：明确本批覆盖的风险类别；
- `window_from`、`window_until`、`checked_at` 和 `effective_until`；
- `source_names` 和 `source_urls`；
- `coverage_complete`；
- `open_event_carry_forward_complete`：上市以来开放事件已经连续结转；
- `reasons`：不完整、失败或范围受限的稳定原因。

只有七类全部覆盖、来源状态正常、覆盖声明完整且在有效期内时，空事件列表才能
返回“已完整检查、当前无有效风险”。否则返回 `missing`、`stale`、
`source_failed` 或 `source_unverified`，不得返回无风险。

覆盖窗口必须从发行人上市时间或更早开始，窗口结束和检查时间距离 `as_of`
均不得超过24小时；覆盖有效期从检查时间起最多24小时。开放事件结转不完整时
返回 `missing`。以上24小时是 D1 来源合同的新鲜度上限，不是风险事件的默认
失效天数。

### 4.4 候选输入

`LeaderRiskInvalidationFeatureInput` 组合：

- 本轮 `as_of`；
- 候选证券和发行人身份；
- 一个查询完整性证明；
- 零个或多个风险事件；
- 零个或多个官方解除或修正证据；
- 调用方提供的来源状态。

## 5. 分类专属规则

### 5.1 减持

- 必须给出公告明确的计划生效区间；
- 缺少 `effective_until` 时返回 `source_unverified`；
- 计划完成、提前终止、撤回或有效期结束后不再列为有效事件，但保留压缩引用。

### 5.2 解禁

- 必须给出明确解禁生效日或区间；
- 缺少 `effective_until` 时返回 `source_unverified`；
- D1 只记录官方解禁事实，不从解禁数量推导正式风险程度。

### 5.3 监管

- 监管问询、监管措施、纪律处分和行政处罚必须保留原文身份；
- `event_subtype` 必须明确区分以上四类；
- 没有明确结束时间时保持有效，直到官方状态或解除证据关闭；
- 普通交易所问询不得自行提升为正式重大风险。

### 5.4 调查

- 立案调查、重大违法调查等必须来自有权机关或公司正式披露；
- 必须提供官方 `case_id`；
- 没有明确结束时间时保持有效；
- 结案、撤案或正式调查结论必须作为独立解除证据。

### 5.5 诉讼

- 必须能精确关联上市公司主体，并保留正式文书或公司公告；
- 必须提供官方 `case_id`，子类型区分重大诉讼和仲裁；
- 缺少案件身份或主体匹配时返回 `source_unverified`；
- 和解、判决履行、撤诉或终结必须由官方材料关闭。

### 5.6 业绩

- 必须包含 `reporting_period`；
- 子类型区分预亏、重大下降和重大减值；
- 预亏、重大下降、重大减值等只记录对应报告期事实；
- 更正公告或正式定期报告可以修正原事件，但不能静默覆盖旧版本。

### 5.7 审计

- 必须包含 `reporting_period` 和审计报告原文；
- 子类型区分保留意见、否定意见、无法表示意见和持续经营重大不确定性；
- 保留意见、否定意见、无法表示意见及持续经营重大不确定性分别保留官方事实；
- 后续消除影响或更正必须由新的正式审计或公司披露材料证明。

## 6. 验证和冲突规则

- 所有时间必须包含时区；发布时间、生效开始、窗口结束和检查时间不得晚于
  `as_of`，事件或覆盖的 `effective_until` 可以晚于 `as_of`，但必须满足
  各自区间和覆盖新鲜度约束；
- `effective_from <= as_of` 才能成为当期有效事件；
- `effective_until` 早于 `as_of` 的事件保留引用但不列为有效风险；
- 证券、发行人、目标事件、文档和报告期身份必须一致；
- 事件、版本、解除证据、文档和覆盖证明身份不得重复；
- 原文链接必须为 HTTPS、不得含用户凭证，并命中来源类型允许的官方域名；
- 来源合同和适配器合同必须命中冻结注册表，覆盖域名必须支持声明的风险类别；
- 同一事件出现多个版本时当前统一返回 `source_unverified`，不得自行选择
  较新版本；
- 事件和解除证据的文档身份必须跨集合唯一；
- 解除证据早于事件、引用不存在或主体不一致时返回
  `source_unverified`；
- 来源失败优先返回 `source_failed`；
- 覆盖证明过期返回 `stale`；
- 输入缺失返回 `missing`。

`ResearchFeatureStatus.READY` 只表示研究合同校验通过，不表示证券没有风险、
适合交易或可以进入正式候选。

## 7. 输出合同

`LeaderRiskInvalidationFeatureResult` 输出：

- `formulaVersion=radar-leader-risk-invalidation-feature-v1`；
- 整体研究状态和稳定原因；
- `coverageState`；
- `activeRiskCategories`；
- 有效事件、已关闭事件和解除关系的压缩引用；
- `noActiveRiskObserved`：只有完整覆盖且当前没有有效事件时才为真；
- `scoreReady=false`；
- `formalUsable=false`；
- `researchScore=null`。

输出不包含完整公告、报告、司法文书、AI 推理、个人身份信息或调用方自定义的
正式严重程度。公开 URL 移除查询参数、片段和凭证；原始文档身份、案件身份和
事实摘要只输出不可逆引用或指纹，不原样返回。

## 8. 运行时边界

D1 首步只实现独立纯计算研究合同和专项测试，不接入现有阶段 6 运行时。
待真实来源适配、覆盖证明和版本仓储完成后，再单独设计运行时可选输入。

因此本阶段始终保持：

- `risk_filter_passed` 不变；
- 正式评分和状态机不变；
- `evidence.invalidation` 不注入未经正式门禁批准的结果；
- 只读 API 和前端不变；
- 阶段 6 生产开关继续关闭。

## 9. 明确不做

- 不自动抓取、下载或解析公告、报告、司法文书；
- 不把旧提醒记录直接转换为 D1 官方证据；
- 不使用新闻、关键词、AI 或市场价格推断风险；
- 不冻结正式风险等级、扣分、移出阈值或有效天数；
- 不新增数据库表、迁移、仓储、调度、API、前端或提醒；
- 不修改环境变量，不启用阶段 6 生产开关；
- 不读取或写入生产 SQLite；
- 不停止或重载 4000/8001；
- 不执行 Git 暂存、提交或推送。

## 10. 测试

专项测试至少覆盖：

- 七类风险事件分别通过合同校验；
- 完整覆盖且空事件返回 `noActiveRiskObserved=true`；
- 空事件但覆盖不全不能声明无风险；
- 来源失败、覆盖过期、未来时间和 HTTP 原文；
- 上市以来覆盖缺口、超过24小时的新鲜度、无界有效期和开放事件结转缺失；
- 未注册来源合同、适配器、官方域名和类别覆盖；
- 减持、解禁缺少结束区间；
- 业绩、审计缺少报告期；
- 调查、诉讼缺少案件身份，以及类别和子类型错配；
- 调查、监管、诉讼保持有效直到官方解除；
- 官方完成、撤回和正式解除；更正不得关闭风险；
- 解除引用缺失、主体错配、时间倒置；
- 精确事件版本引用、跨集合重复文档和有效版本冲突；
- 已过期事件保留压缩引用但不列为有效风险；
- URL凭证拒绝、查询参数脱敏和缺失集合稳定状态；
- 非字符串摘要、非法类别和其他嵌套字段类型返回稳定降级，不抛异常；
- 输出不包含完整原文，正式分数与可用标记保持关闭；
- 现有 B3 主营证伪合同和阶段 6 正式门禁保持不变。

完成专项测试后运行全部龙头测试和必要后端回归。任何导入 `main` 的测试必须先
将生产 SQLite 精确路径重定向到初始化后的临时库。最后运行相关语法检查和
`git diff --check`。

## 11. 回退

回退只需撤回独立研究模块、对应测试、实施计划和本文档。现有状态机、评分、
数据库、API、阶段 6L-A/B/C、旧提醒链路和阶段 5 影子观察不受影响。
