# 阶段9真实向前回放基线设计

## 1. 目标

在不读写生产 SQLite、不用当前值回填过去的前提下，将现有真实官方来源转换为阶段9严格时点回放证据，并生成第一份可重放的向前观察基线和质量报告。

首轮只记录本轮抓取完成之后的 `asOf`，不尝试重建早于抓取时间的世界。任一来源无法证明历史生效时间时，保持 `unverifiable`；公司行为全市场历史源缺失时，保持 `missing`。

## 2. 来源路由

- 证券范围：复用上交所、深交所和北交所官方证券主档采集器，保留代码、名称、交易所、板块、上市日期和原始字段。该快照只从首次成功抓取时点向后有效。
- 交易规则：复用已版本化的沪深主板、科创板和创业板官方规则目录。北交所未进入同一目录时不得声称全市场完整。
- 行业：复用中上协官方发布页和 PDF，必须与本轮证券主档对齐，保留文档 SHA-256、发布日、首次观察时间、知识生效时间和映射缺口。
- 指数：首轮使用中证指数官方基本信息、方案 PDF和成分文件建立一个代表性快照。若公告日或生效日缺失，数据可作当前向前观察，但回放域仍标记 `unverifiable`。
- ETF：复用沪深交易所官方上市基金产品主档，保留产品类型、资产类别、上市日期、分类映射版本和未确认原因。
- 公司行为：定义同样的显式快照适配口，但首轮不新造来源。无全市场、带原始发布时间和生效时间的官方工件时输出 `missing`。

## 3. 合同与数据流

新增六个纯转换适配器，它们只接受已获取的强类型来源对象，输出 `RadarReplayEvidence`，不发起网络请求、不访问数据库。每份证据保留原来源合同、原始时间、抓取时间、生效时间、行数、完整度、原因码和内容哈希。

向前基线采集器负责调用现有真实来源，在全部请求结束后冻结样本 `asOf`。因此每个已接受来源的 `fetchedAt <= sample.asOf`。采集器把完整来源快照、回放输入和质量报告原子写入调用方显式提供的 `/private/tmp` 目录，不写默认生产运行仓。

## 4. 首批样本语义

首轮只产生一个 `development` 向前观察样本。评估器必须额外报告缺失的 `calibration` 和 `holdout` 分区；后续不同时点的新样本才能分别进入这两个分区，不复制首份样本、不改写身份。

首份报告预期为 `not_ready`，因为当前公司行为历史源缺失，指数或其他来源也可能因生效时点不可验证被排除。这是首份真实质量基线，不是工程失败。

## 5. 失败与安全边界

- 来源请求失败与来源内容不可验证分开。
- 任一时间无时区、晚于样本 `asOf` 或身份重复时失败关闭。
- 输出目录必须在 `/private/tmp`，不读写生产 SQLite，不修改默认回放报告仓。
- 不计算胜率、收益、命中率或黄金标签；没有独立真实标注时指标继续为 `null`。
- 不新增依赖、数据库迁移、环境变量、调度、正式开关、AI 调用或服务重载。

## 6. 验收

- 六个历史域均有稳定转换合同和失败语义。
- 真实向前基线保留原始来源身份、时间、哈希和数量。
- 缺少公司行为或分区时报告为 `not_ready`，不伪造完整。
- 回放输入、质量报告和内容哈希可从落盘工件重新校验。
- 相关测试、完整后端、Python 编译、`pip check`和 `git diff --check` 通过。
